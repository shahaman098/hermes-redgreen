# Tamper-detection benchmark

Reproduce: `python3 benchmarks/run_benchmarks.py` (writes nothing unless you pass `--json`).

## Method and honest limits

50 synthetic before/after Python test files: **30 tampering** (assertion deleted, weakened to a constant, skip
injected, test deleted) and **20 honest** edits (test added, assertion added, expectation edited, comment removed).
The scenarios are generated by the script, so they are a regression suite for this guard, not a sample of the wild.
Both columns run on identical inputs. "Text counter (v1.0)" is the earlier RedGreen logic: regex counts only.
Every number below is computed by the script, not typed in.

## Detection

| System | Tamper caught | False positives (20 honest) |
| --- | :---: | :---: |
| AST guard (this version) | 30/30 (100.0%) | 0 (0.0%) |
| Text counter (v1.0) | 20/30 (66.7%) | 5 (25.0%) |

| Category | n | AST | Text counter |
| --- | :---: | :---: | :---: |
| assertion deleted | 10 | 10/10 | 10/10 |
| weakened to constant | 10 | 10/10 | 0/10 |
| skip injected | 5 | 5/5 | 5/5 |
| test deleted | 5 | 5/5 | 5/5 |

The text counter misses every `assert x` -> `assert True` rewrite (the assertion count does not move) and raises a
false alarm whenever a comment that mentions the word `assert` is deleted.

## Cost

About 0.0852 ms per file check (p50), p99 0.0949 ms. The
real cost of RedGreen is the second test run, not the guard.

## What this does not show

It does not show that the guard catches a weakening that keeps a real expression (for example `== 4` -> `>= 0`).
That case is left to the negative control: such a test cannot fail on the old tree, so the fix stays UNPROVEN.
